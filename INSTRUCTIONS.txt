INSTRUCTIONS FOR CLAUDE: WHAT TO READ FOR WHICH TASK
====================================================
Read this file at the start of every session, and again whenever the conversation has been
summarised or compacted (memory reset). Then read the files listed for the kind of task you have.

ALWAYS (every session, every reset)
  1. CLAUDE.md          project idea, stack, architecture, conventions
  2. PROGRESS.md        what is done, what is next, known gaps
  3. THINGS_TO_ASK.txt  open questions and assumed values (do not present them as facts)

TASK: change or add a rule, threshold or flag text
  - rules.json                 single source of truth for thresholds and sources
  - docs/ (regulations) and docs/Sources/ (reference ships: NOAA SWATH report, three general arrangements)
  - src/engine/rules.ts        one function per rule id; every finding needs message, detail, fix
  - THINGS_TO_ASK.txt          add a question if a value is not from a downloaded document
  - tests/rules.test.ts, tests/features.test.ts

TASK: physics (hydrostatics, weights, stability, flooding, resistance, motions)
  - src/engine/vessel.ts       adapter to vessel.js (use boundedWaterline, never minX = 0 directly)
  - src/engine/stability.ts, src/engine/flooding.ts
  - src/vendor/vessel/PATCHES.md   what was changed in vessel.js and its known bug
  - tests/physics.test.ts      add an analytic check for any new physics

TASK: escape routes or evacuation
  - src/engine/topology.ts, src/engine/evacuation.ts
  - docs/REG13_Means_of_Escape.pdf, docs/MSC.1-Circ.1533_Evacuation_Analysis.pdf
  - tests/evacuation.test.ts

TASK: 3D view, editing, test mode animations
  - src/ui/three/Viewport.tsx  scene, interaction (window-level pointer moves), test animations
  - src/ui/store.ts            state, undo/redo, overlap-safe editSpace, live values for dials
  - scripts/e2e.mjs            browser test; run it after any interaction change

TASK: panels, layout, menus, theme, report
  - src/ui/App.tsx (menus, build bar, tool rail), src/ui/panels.tsx, src/ui/Inspector.tsx
  - src/ui/TestPanel.tsx (dials), src/ui/help.tsx (guide, sources, tour), src/ui/report.ts (PDF)
  - src/index.css (theme tokens: bg, surface, surface-2, line, fg, muted, accent)

TASK: pipes and cables (fire main, bilge and ballast, fuel oil, exhaust, HV and feeder cables)
  - src/engine/systems.ts      run geometry: deckhead height, segments, rooms and bulkheads crossed, clearances
  - src/engine/generators.ts   defaultRuns (default arrangement for the demo and the model ships)
  - src/engine/rules.ts        PIPE-FIRE-MAIN, PIPE-WATERTIGHT, PIPE-FUEL-HOT, CABLE-ROUTING
  - src/ui/three/runs.tsx      3D tubes, draw-in animation, hover, handles, pins; drawing is in Viewport Interaction
  - docs/REG10_Fire_Fighting.pdf, docs/IACS_SC11_Cable_Routing_II-1_45.pdf, docs/MSC_Circ647_Flammable_Leakage.pdf,
    docs/IACS_SDC8_Watertight_Penetrations_II-1_13.pdf
  - tests/systems.test.ts, scripts/check-systems.ts (prints the four checks for every model ship)

TASK: Fix with AI (automatic fixes for flags, optional AI choice, animated run)
  - src/engine/fixes.ts        catalogue of fixes per rule, verification on the whole analysis, planner
  - src/engine/fixWorker.ts    runs the planner in a Web Worker
  - src/ui/FixDirector.tsx     the animated run (camera, tweens, rings) and the bar with Pause / Skip / Stop
  - src/ai/client.ts, netlify/functions/fix-choice.mts   OpenRouter call (key only on the server)
  - tests/fixes.test.ts, scripts/e2e.mjs (stand-in AI via window.__fakeAI)
  - A new rule needs a catalogue entry in fixes.ts if it can be fixed automatically; otherwise it is listed as
    "left for a designer". The AI never sets a verdict or geometry, it only picks a verified option.

TASK: file import / export
  - src/engine/io.ts (design JSON, vessel.js JSON, offsets CSV), src/ui/App.tsx loadMesh (STL/OBJ/glTF)
  - src/engine/shipFiles.ts    ship as CSV tables (export and import, table found from its header row)
  - src/engine/glb.ts          writes an exterior .glb in ship coordinates (tagged, placed without scaling)
  - src/ui/shipImport.ts       File > Import ship files (several at once, drag and drop), Open example
  - src/data/rcrv.ts, src/data/rcrvExterior.ts   RCRV research vessel rebuilt from the Navisworks views;
    scripts/build-rcrv.ts writes public/models/rcrv/ (run it after changing either file; a test checks it)
  - scripts/check-rcrv.ts      prints the RCRV analysis; --calibrate GM recomputes the lightship
  - tests/io.test.ts, tests/features.test.ts, tests/shipFiles.test.ts, scripts/e2e.mjs (upload section)

BEFORE SAYING A CHANGE IS DONE
  npm test            unit and physics tests
  npm run typecheck
  npm run dev  then  npm run e2e   (browser test, needs Chrome or Edge)
  npm run report      prints the demo ship analysis in the terminal
  Update PROGRESS.md (status and to-do) at the end of a work session.
